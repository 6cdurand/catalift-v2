## NEW bugs

### F-1 (major): starting a program session loads an empty workout

Client `/today` → "Start Push" → `/workout/active` has no exercises ("Sets done 0/0", no blocks; persists after hard refresh).

- `src/app/(app)/today/page.tsx:72-74` — `handleStart` only does `router.push("/workout/active")`; the program day's exercises are never seeded into the active-workout store.
- `src/lib/programStartUtils.ts` (day → `startFromTemplate` conversion, see `:85-127`) has **no callers** in `src/`.
- Same pattern in `src/features/programs/client/ClientProgramPage.tsx:37-39`.

**Impact:** blocks the intended program-execution UX; sessions are still recordable by manually adding exercises.

### D-1 (moderate): calendar marks pre-start dates as "Missed"

Assign a fixed-days program starting today → client `/calendar` marks matching weekdays **before the program start date** (e.g. Thu Jul 23 "Pull — Missed" for a program starting Jul 28) as red Missed.

- `src/features/calendar/lib/selectors.ts:104-143` — `buildFixedSessions` iterates the whole requested range and never clamps to `program.startDate`.
- `src/features/calendar/lib/selectors.ts:91-95` — `deriveStatus` then returns `"missed"` for any scheduled `date < today`, including dates before the program existed.
- Surfaced via `useScheduledSessions` (`src/features/calendar/hooks/useScheduledSessions.ts:189-198`).

### Minor observations

1. Hard refresh on `/workout/active` after finishing silently starts a brand-new empty session (timer restarts) instead of leaving the workout context.
2. Trainer signup's first `/today` render shows the athlete-style panel until refresh.
3. Product check: saving a one-off demotes the active multi-week program to "Past Programs" on the trainer's client-file Programs card (still labelled active).
