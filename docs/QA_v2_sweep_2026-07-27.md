## New bugs / blockers found

### 1. INVITE SECURITY: a logged-in user can accept an invite sent to a different email

**Severity:** Security / regression vs expected invite semantics.

**Repro steps:**
1. As trainer, create an invite for `edge@catalift.test` (`/clients` → `Add Client` → `Create New`).
2. In a different browser/incognito context, sign up as `other@catalift.test` (or any other account).
3. While still logged in as `other@catalift.test`, open the invite link copied in step 1.
4. The invite page immediately shows `Welcome to Catalift! Your account has been linked. Redirecting you to the app...` and binds `other@catalift.test` to the trainer.
5. The trainer roster now lists the wrong user as an active client.

**Root cause observed in repo:**
- `supabase/migrations/20260722000000_00013_reconcile_invitations_and_advisor_revoke.sql` lines 78-112: `accept_invitation(p_token text)` creates the `trainer_clients` row using `auth.uid()` only; it does not compare `auth.email()` to the invited email stored in the token.
- `src/app/invite/page.tsx` (and/or `useInvite` hook) auto-accepts a valid invite on mount if a user is already signed in, without verifying the invite email matches the current user's email.

**Impact:** Any logged-in user who clicks (or is redirected to) any valid invite link is silently added to that trainer's roster. This is a clear permission/safety issue.

**Regression vs v1 parity:** Likely a regression — v1 invite flows typically required either signing up with the invited email or explicit acceptance by the intended recipient.

---

### 2. Calendar direct load shows the session only as a dot until the date is clicked

**Severity:** UX / observation (not a data-loss bug).

**Repro steps:**
1. Trainer assigns a one-off workout to a client.
2. Client logs in and navigates directly to `/calendar` (or hard-refreshes).
3. Today's date shows a blue `Upcoming` dot and the legend shows `Upcoming`.
4. The session title (`PT Session`) is not displayed until the user clicks today's cell.

**Impact:** The data is present and survives direct load (so D.4 passes), but the session title is not immediately visible. This may not match user expectations for a calendar agenda view.

**Regression vs v1 parity:** To be confirmed with product — v1 may have shown a list or card below the grid by default.
